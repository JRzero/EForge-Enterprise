# ADR 0018：有界的人工任务创建与作业恢复

状态：Accepted（在已授权的 Flowable 失败任务运维范围内；实现与验收另见任务清单）。

目前纯同步人工审批不会产生可重试的异步作业。为交付真实失败作业运维，增加独立、默认关闭的异步开关，并只允许开始事件直接连接的第一个人工任务使用 `flowable:async="true"`。其他节点的异步、异步离开、定时器、脚本、服务调用和用户监听器仍被拒绝。普通同步流程保持原行为。

异步只延后创建首个人工任务，不替人批准，也不异步更新审批结果。申请与引擎作业、关联、提交审计仍在同一主库事务提交；执行器只在提交后可见该作业。执行时再次核验当前候选资格。异步开关关闭时不得激活或发起依赖它的流程，但保留读取、诊断与原有同步审批。

运维查询和重试使用专用权限及同一规范 API。恢复只面向框架已发布且关联有效待审申请的有界作业；重新入队与运维审计共同提交，不提供任意引擎命令、跳转、变量修改或删除历史。响应明确为等待执行，只有实际任务生成才说明恢复成功。暂停实例/定义不得被重试操作绕过。

必须证明：真实 SQL 故障令官方执行器重试并进入死信；恢复条件后重新入队并实际生成唯一待办；幂等、并发、撤权、审计故障、撤回与执行竞争均保持一致。默认关闭、独立开关和失败状态不得伪装为已执行。

官方依据：[异步执行器与死信](https://www.flowable.com/open-source/docs/bpmn/ch18-Advanced/)、[固定 7.2.0 ManagementService](https://github.com/flowable/flowable-engine/blob/flowable-7.2.0/modules/flowable-engine/src/main/java/org/flowable/engine/ManagementService.java)。不改变模块化单体、数据源或 Flowable 版本，不隐式启用生产执行器。
