# Generated React pages: current implementation and validation boundary

The eforge-react target now renders actual Page.tsx, a static route export and a
pinned OpenAPI client generation script for CRUD, tree and master/detail output.
Original Java/backend compatibility files remain; the React target no longer
silently falls back to a Vue page. Other original frontend template choices remain.

Generated pages consume pinned EForge UI/patterns/data packages, original session
contexts, original dictionary and sanitized rich-text components. Database metadata
is emitted as encoded literals and explicit field descriptors. Component imports
and route components are static. The generated client uses the actual installed
business OpenAPI operations and schemas, is generated twice byte-identically, and
supplies strict model/write/query types and derived actual query bindings.

The host authenticatedFetch accepts only normalized same-origin /api/v1/business
paths before attaching credentials. Existing timeout/abort/401 behavior is retained.
File upload uses an explicit original AjaxResult compatibility boundary and validates
the returned owned profile path. Two targeted host tests pass; total frontend81,
lint/typecheck/client reproduction/build pass.

The compiler assembles actual generated Java/XML in original Boot, then captures
its actual canonical OpenAPI. The React verifier copies actual emitted files to an
owned temporary feature directory, generates actual clients, strictly compiles all
three pages/routes and checks the repository React/lint rules. Real browser
validation mounts the emitted page with original session runtime and pinned EForge
providers, authenticates through original JWT/Redis, and checks SQL-backed writes,
exact identifiers/decimals, XLSX, deletion, literal hostile HTML and no-role refusal.
It uses isolated parent-owned fixture tables/users and unique temporary output.
It does not install production routes or claim full host navigation acceptance.

Strict compilation exposed nullable metadata labels and tree field binding errors;
lint exposed duplicate ID helpers and unused tree pagination state. Those were
fixed in the emitted source. Browser preparation exposed missing non-increment
child primary-key input; child controls now keep that original required capability.
The first browser execution reached CRUD mutation/export/delete, then revealed
a missing logout proxy in the probe; the second reached real no-role denial but
incorrectly assumed the host transport returned rather than threw a403. Both probe
errors are corrected without weakening product authentication.
