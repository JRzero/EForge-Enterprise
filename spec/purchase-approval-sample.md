# 采购审批示例

状态：实施中。用户于2026-10-21确认单级指定审批人，先跑通完整闭环。

## 目标与范围

在现有模块化单体与 React 外壳内交付独立采购示例，复用公共列表、编辑、明细、精确数值、附件与审计组件。业务类型为 purchase，与 leave 的数据、激活版本、任务和权限隔离。示例业务规则保持局部，不引入动态表单引擎、库存、付款、供应商主数据或多租户。表单构建器仍暂缓。

申请人维护草稿（标题、用途、指定审批人、明细、附件），提交后审批人通过/驳回，申请人可在待审时撤回。第一版不提供转交、加签、金额分级或审批后修改。驳回/撤回为终态，新申请使用新业务标识。

## 数据与权限

- 主表、明细、审计与附件独立归采购功能所有；禁止把采购字段写进请假单。
- 数量最多3位小数，单价最多2位小数，均使用十进制字符串作为HTTP输入；后端BigDecimal计算每行金额（人民币、HALF_UP到分），总额为已舍入行金额之和。禁止NaN、科学计数法、负数、零数量、精度超限及溢出；不得信任前端总额。
- 每张申请1–100行；标题1–100字、用途1–1000字；数量上限999999.999，单价上限99999999.99，总额上限999999999999.99。行标识稳定且不重复。
- 登录身份来自服务端；普通用户仅看自己的申请或自己被指定且已提交的审批。管理员身份不绕过业务参与者隔离。草稿仅本人可见。
- 指定审批人必须启用且具有采购审批权限，不能指定本人；提交和决策时重新校验。无角色不等同管理员。
- 修改/提交/决策/撤回采用expectedRevision与commandId；同命令同内容重试不重复执行，同命令不同内容409；并发决策至多一个成功。
- 附件按申请鉴权，最多5个、单文件5MB，限定PDF/PNG/JPEG并核验内容；下载作为attachment返回，不暴露磁盘路径；附件更改仅草稿本人允许。附件存储实现不得沿用匿名profile URL冒充访问控制。

## Flowable边界

复用官方引擎、流程包校验/发布/激活及主库事务边界，业务表、引擎执行和审计同事务提交。采购流程仅允许一个同步人工任务，assignee为现有安全白名单 `${approver}`，结束节点approvedEnd/rejectedEnd；审批人变量仅由服务端从已验证草稿填写。第一版拒绝采购异步节点，保留原请假异步能力。生产默认关闭工作流不变。

新增purchase发布时必须同时验证采购绑定与批准/驳回场景，不仅放宽businessType正则。采购激活不得覆盖leave；不可自动部署/自动激活用户工作流。

## 接口与页面

规范入口 `/api/v1/samples/purchases`，具体DTO、PageResponse与ProblemDetail，客户端从真实OpenAPI生成。草稿create/update、mine/pending/handled列表、参与者详情、submit/decision/withdrawal、审批人选择、附件上传下载删除。列表有分页、状态筛选；编辑采用稳定明细行与错误定位；详情展示状态、金额、附件、审计和有权限的动作。路由/menu_key固定，不从数据库字符串动态解析组件。

## 验收

1. 先以测试证明金额精度、不可变明细与边界拒绝；HTTP与持久化使用同一后端规则。
2. 真实MySQL+Flowable证明草稿、提交、批准、驳回、撤回；重复/并发/过期版本；审计写失败使业务及引擎一起回滚；leave/purchase隔离。
3. 真实登录与两账号浏览器证明权限、参与者隔离、审批人失效、附件鉴权；禁用工作流返回明确不可用状态。
4. 生成客户端可复现，实时OpenAPI一致，前端lint/typecheck/test/build、相关模拟与真实浏览器、完整Maven及原数据范围测试通过。
5. 未实测前不得宣称完成；不对运行中jar打包，不自动修改已有开发/生产数据库。

验证命令沿用 docs/agent-workflow.md；新增实际环境脚本须使用其拥有的独立测试数据和端口。新增API/菜单/SQL必须接入完整回归，最终按精确SHA核对云端。
